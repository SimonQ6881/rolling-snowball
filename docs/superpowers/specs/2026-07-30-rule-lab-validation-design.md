# Rolling Snowball 规则实验台阈值校验增强设计

## 1. 背景

当前规则实验台已经具备以下能力：

- 默认规则读取
- 硬过滤阈值编辑
- 一级维度权重与二级指标权重编辑
- `key_watch_top_n` 编辑
- 权重总和校验
- 改动高亮、改动摘要、恢复默认

但当前页面对“字段值本身是否合法”的拦截仍然偏弱。用户可以很容易输入明显不合理的值，例如：

- 比例型字段小于 `0` 或大于 `1`
- 金额型字段为负数
- `key_watch_top_n` 不是正整数
- 权重字段超出 `0-1`
- 输入框处于空值或非法数值状态

这些问题虽然最终可能被后端校验兜底，但前端没有及时提示，会带来两个问题：

1. 用户不知道当前值已经越界
2. 用户只能在提交时才发现错误，反馈太晚

因此，这一轮设计聚焦规则实验台的“阈值越界校验”，优先把最确定、最明确、最应该前置拦下的错误放到前端即时交互里。

## 2. 目标

本次增强目标如下：

- 对规则实验台中的关键数值字段提供即时合法性校验
- 明确区分“硬错误”和“软提醒”
- 让字段级、分组级、页面级错误提示联动
- 只要存在硬错误，就禁止提交运行
- 保留后端现有校验作为最终兜底

## 3. 非目标

本次明确不做以下内容：

- 复杂参数组合冲突判断
- “这套规则可能筛不出股票”的结果预测
- 行业分布或样本量模拟
- 新的后端规则校验体系重写
- 复杂的业务经验型建议系统

本次只解决“字段值本身是否合法”以及“页面如何及时提示并拦截”的问题。

## 4. 总体方案

采用 `前端即时校验 + 后端最终兜底` 的方式。

前端负责：

- 输入后立即校验
- 维护字段级错误表
- 生成分组级错误统计
- 控制顶部摘要和提交按钮状态

后端继续负责：

- 最终规则校验
- 防止绕过前端直接提交非法配置

本次不新增后端接口，优先在前端补齐体验层能力。

## 5. 字段分类与校验规则

## 5.1 比例型阈值

本次纳入该类的字段：

- `exclude_asset_liability_ratio_gt`
- `exclude_cash_conversion_ratio_3y_lt`

校验规则：

- 必须是数字
- 不允许小于 `0`
- 不允许大于 `1`

错误文案：

- `请输入 0 到 1 之间的数值`

## 5.2 金额型阈值

本次纳入该类的字段：

- `exclude_market_cap_lt_cny`
- `exclude_avg_turnover_20d_lt_cny`

硬校验规则：

- 必须是数字
- 不允许小于 `0`

硬错误文案：

- `请输入大于等于 0 的数值`

软提醒规则：

- 若值极低但仍大于等于 `0`，提示筛选约束可能偏弱

软提醒文案：

- `当前门槛较低，筛选约束可能偏弱`

本次不写死业务下限，例如“不得低于 1 亿”，避免把越界校验和策略判断混在一起。

## 5.3 整数型阈值

本次纳入该类的字段：

- `key_watch_top_n`

校验规则：

- 必须是数字
- 必须是整数
- 必须大于等于 `1`

错误文案：

- `请输入大于等于 1 的整数`

## 5.4 权重字段

本次虽然不增强权重结构校验，但对单字段边界补最基础的合法性校验。

适用范围：

- 一级维度权重
- 二级指标权重

校验规则：

- 必须是数字
- 不允许小于 `0`
- 不允许大于 `1`

错误文案：

- `请输入 0 到 1 之间的数值`

权重总和是否为 `1` 的结构校验，继续沿用现有逻辑。

## 6. 提示层级设计

## 6.1 字段级

字段级提示是本次最主要的信息承载层。

若字段存在硬错误：

- 输入框边框切到错误态
- 字段下方展示红色错误文案

若字段存在软提醒：

- 保持普通或轻提醒态
- 字段下方展示弱提示文案

同一字段同时有硬错误时，不显示软提醒，避免信息冲突。

## 6.2 分组级

分组标题显示当前组的错误数量。

展示示例：

- `硬过滤阈值 · 2 项错误`
- `一级维度权重 · 1 项错误`

若当前分组没有硬错误，则不需要强制展示错误计数。

## 6.3 页面级

顶部摘要区额外显示：

- 当前硬错误字段数
- 当前是否允许提交

展示规则：

- 无硬错误：显示 `当前字段均合法`
- 有硬错误：显示 `当前有 X 个字段不合法，修正后才能运行`

该信息与现有“改动摘要”并存，但语义分开，不混成一条笼统提示。

## 7. 交互与拦截规则

## 7.1 输入时机

每次字段值变化后立即触发校验：

1. 更新字段级错误状态
2. 更新分组级错误计数
3. 更新页面级错误汇总
4. 联动提交按钮禁用状态

不需要等到点击提交才触发。

## 7.2 提交拦截

只要存在任何硬错误：

- 禁止点击运行按钮
- 顶部和提交区都显示拦截提示

若不存在硬错误，但权重总和不平衡：

- 继续按现有规则禁止提交
- 文案继续区分“字段越界错误”和“结构未平衡”

若只有软提醒：

- 允许提交
- 保留轻提醒提示

## 7.3 与改动高亮共存

本次新增的校验提示必须与现有改动高亮共存。

优先级建议如下：

1. 硬错误
2. 已修改
3. 软提醒

也就是说：

- 若字段既被修改又越界，应优先显示错误态
- 仍可保留“已修改”标签，但视觉上以错误为主

## 8. 错误与边界情况

## 8.1 空值与非法数值

若输入框出现：

- 空字符串
- `NaN`
- 非法数值

一律视为硬错误。

## 8.2 默认规则加载失败

若默认规则加载失败：

- 继续沿用上一轮设计中的错误页面
- 本次校验逻辑不再单独展示

## 8.3 合法值恢复

若用户把非法值改回合法区间：

- 字段级错误立即消失
- 分组级错误计数同步减少
- 若全页已无硬错误，则恢复按钮可用性判断与提交逻辑

## 9. 数据与实现边界

本次增强以前端为主，不新增接口。

建议新增一个轻量辅助模块：

- `frontend-console/src/lib/ruleValidation.ts`

职责包括：

- 单字段校验
- 字段错误收集
- 软提醒收集
- 分组级错误统计
- 页面是否允许提交的汇总判断

页面主要改动文件：

- `frontend-console/src/pages/LabPage.tsx`

## 10. 测试方案

本次至少覆盖以下测试：

### 10.1 字段越界

- 比例型字段输入 `-0.1`、`1.2`
- 金额型字段输入负数
- `key_watch_top_n` 输入 `0`、小数、空值
- 权重字段输入 `-0.2`、`1.3`

### 10.2 页面拦截

- 只要存在硬错误，提交按钮禁用
- 顶部摘要显示错误数量
- 对应分组显示错误提示

### 10.3 合法值恢复

- 从非法值改回合法值后：
  - 字段错误消失
  - 分组错误数更新
  - 页面重新允许提交

### 10.4 软提醒不拦截

- 金额阈值较低但不越界时：
  - 出现软提醒
  - 仍然允许提交

### 10.5 与现有结构校验共存

- 字段都合法，但权重总和不为 `1` 时：
  - 仍然禁止提交
  - 文案与字段越界错误区分开

## 11. 验收标准

满足以下条件即认为本次增强完成：

1. 关键数值字段都能即时识别越界
2. 用户能在字段、分组、页面三个层级看到错误
3. 任何硬错误都会阻止运行
4. 软提醒不会阻止运行
5. 现有改动高亮、权重平衡校验、任务创建流程不被破坏

## 12. 实施顺序建议

建议按以下顺序实现：

1. 抽离字段校验逻辑
2. 生成字段级错误与提醒
3. 接入分组级错误统计
4. 接入页面级摘要与提交拦截
5. 补充测试与浏览器验收
