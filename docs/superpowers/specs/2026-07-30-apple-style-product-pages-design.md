# Rolling Snowball 苹果风格产品页改造设计

## 1. 背景

当前 `rolling-snowball` 主线前端已经具备完整的研究闭环能力，但整体视觉仍然更像一套深色内部控制台：

- 大面积深色背景与青色高亮使页面更偏“工具感”
- 首页、列表、详情、实验台的视觉节奏不够统一
- 信息组织普遍偏“并列堆叠”，缺少产品级主次关系
- 关键结果、摘要结论、操作入口都在同时争夺注意力

用户希望把整套主线页面统一优化为更接近 Apple 官网感的产品级界面，但不是做成纯展示页，也不是推翻现有主线功能，而是在保留业务逻辑和研究效率的前提下完成视觉与信息重构。

## 2. 已确认方向

本次设计已经与用户逐步确认，最终方向如下：

- 风格方向：`Apple 官网感`
- 明暗基调：`浅色主导`
- 改动深度：`视觉 + 信息重构`
- 范围：`整套主线页面`
- 标题策略：`克制标题`

用户确认采用的视觉规则为：

- `1` 主色板改为暖白、浅灰、蓝灰
- `3` 卡片更轻、更圆、更弱边框
- `4` 表格更安静、更排版化
- `5` 按钮更克制
- `6` 页面密度分层：首页与摘要页更松，工作区更紧

用户未采用的规则为：

- `2` 全站强化大标题层级

因此，本次不会把整套主线做成强烈宣传页语气，而是会做成“具有 Apple 官网高级感的专业研究工作台”。

## 3. 目标

本次改造的目标是：

- 让主线页面第一眼更像成熟产品，而不是内部工具
- 在不改动业务逻辑的前提下，重构页面主次层级和视觉节奏
- 统一首页、列表、详情、复盘、任务、实验台的视觉语言
- 提升结论区、摘要区和操作区的辨识度
- 保留高频研究操作的可读性和效率

本次不包含：

- 改动后端接口
- 改动路由含义
- 改动核心业务流程
- 新增与本次视觉改造无关的新功能

## 4. 范围

### 4.1 在范围内的页面

本次覆盖当前主线页面：

- `/` 首页 / 重点观察池
- `/stocks` 股票列表
- `/industries` 行业看板
- `/stocks/:tsCode` 个股详情
- `/runs` 历史运行
- `/run-review` Run 质量总览
- `/lab` 规则实验台
- `/tasks/:taskId` 任务页

### 4.2 在范围内的公共层

- `AppShell` 框架层
- 全局色板、背景、阴影、圆角、字体层级
- `Panel`、`MetricTile`、`StatusPill` 等基础视觉容器
- 主按钮、次按钮、筛选器、输入框、表格、状态标签

## 5. 总体设计原则

### 5.1 产品化工作台

整套页面要从“深色控制台”切换为“浅色产品级工作台”。

这意味着：

- 页面先展示最重要的结论或摘要
- 操作入口降为辅助层，而不是与内容并列抢焦点
- 同类信息通过统一卡片系统和留白节奏组织
- 页面之间应共享同一套视觉语法，而不是各自独立堆样式

### 5.2 克制的 Apple 感

视觉目标是接近 Apple 官网与专业产品页的交叉区间，而不是生硬模仿营销页：

- 保留产品级高级感
- 避免过强宣传文案感
- 避免全站大标题泛滥
- 避免过度玻璃拟态导致数据阅读变差

### 5.3 摘要优先

所有关键页面优先回答“现在最值得看什么”，再进入明细、筛选、解释和操作。

适用范围：

- 首页先看本次 run 的重点结论
- 详情页先看个股结论与状态
- Run 复盘页先看有没有跑偏
- 任务页先看当前状态与结果入口
- 实验台先看改动摘要、校验状态和提交决策

### 5.4 密度分层

不是整站统一做得很松，而是按页面角色分层：

- 首页、Hero、摘要区：更松
- 列表页和详情数据区：中等密度
- 实验台编辑区、筛选区、表格区：相对更紧

## 6. 视觉语言

### 6.1 色板

整体色板调整为：

- 主背景：暖白、浅灰白、雾灰
- 表面层：半透明白、浅灰卡片、浅蓝灰强调面
- 主文字：深灰黑
- 次文字：中灰、蓝灰
- 高亮色：减少当前青色，改为更克制的深灰按钮与少量蓝灰强调

状态色继续保留，但语气要更柔和：

- 成功：浅绿底 + 深绿色文字
- Warning：浅杏黄底 + 深金棕文字
- 风险 / 过滤：浅红底 + 深红文字

### 6.2 卡片系统

卡片应成为主视觉骨架，规则如下：

- 大圆角，统一提升到更接近 Apple 产品卡片的级别
- 边框弱化，不再依赖厚边框分组
- 主要依赖半透明白、极浅底色和柔和阴影建立层级
- 大卡片承载摘要和主结论，小卡片承载指标或辅助入口

### 6.3 按钮系统

按钮采用更克制的产品级规则：

- 主按钮：深色实心，强调单个最重要动作
- 次按钮：浅底或轻描边，不与主按钮争焦点
- 同一区域不同时出现多个高饱和高亮按钮
- 文案更简洁，避免像后台工具按钮那样机械堆叠

### 6.4 表格与列表

表格与列表不应继续沿用典型后台风格，应转为更安静的 Apple 式数据阅读体验：

- 弱化线框分隔
- 强化行距、列距和文字层级
- 关键状态只通过少量状态标签和数值强调体现
- 筛选摘要和结果摘要与表格主体分层展示

### 6.5 标题层级

标题策略采用“克制标题”：

- 首页和少数摘要区可以使用更大的标题
- 列表页、详情页、实验台、任务页不走营销站式夸张大标题
- 更多依赖分组标题、眼眉标题和信息层次，而不是单纯放大字号

## 7. 框架层改造

### 7.1 AppShell

`AppShell` 是本次改造的第一优先级。

当前问题：

- 深色渐变背景较重
- 侧栏和页头整体偏厚
- 视觉语言更接近内部控制台

改造方向：

- 整体切换为浅色主背景
- 侧栏改为更轻的产品级导航容器
- 页头改为更克制的 Hero / 标题区
- 页面主内容与外框层次通过浅色卡片和留白建立

### 7.2 公共组件

以下组件应统一调整：

- `Panel`
- `MetricTile`
- `StatusPill`
- `RunSwitcher`

调整目标：

- 保持组件职责不变
- 统一圆角、边框、阴影、背景透明度
- 统一标题、说明文字和状态标签层级

## 8. 页面级设计

### 8.1 首页 `/`

首页不再是“快捷入口集合页”，而是“本次 run 的产品级摘要页”。

建议结构：

1. Hero 区
   - 展示当前 run 最值得关注的结论
   - 展示 run 时间、规则版本、关键摘要
2. 关键摘要区
   - 重点观察池
   - 通过硬过滤数量
   - 重点池 / 观察池数量
3. 辅助入口区
   - 历史运行
   - 全股票列表
   - 行业看板
   - 规则实验台
4. 重点观察池结果区
   - 作为首页主体内容收尾

首页的重点是“先告诉用户该看什么”，不是先展示所有可点入口。

### 8.2 股票列表 `/stocks`

列表页改造为“摘要 + 过滤舱 + 安静表格”的结构。

建议结构：

1. 顶部摘要区
   - 当前 run
   - 结果量
   - 当前筛选摘要
2. 过滤舱
   - 关键词
   - 池子
   - 过滤状态
   - 行业
3. 表格主体
   - 更安静的数据列表
   - 弱分隔、强排版

改造重点不是增加更多筛选，而是把现有筛选组织得更像专业产品。

### 8.3 行业看板 `/industries`

行业看板应与股票列表共享同一套浅色视觉语法：

- 顶部保留 run 和筛选上下文
- 行业卡片更产品化
- 行业分布与重点池数量要更容易扫读
- 与股票列表之间的跳转关系保持一致

### 8.4 个股详情 `/stocks/:tsCode`

详情页改为“结论先行”的结构。

建议结构：

1. 结论区
   - 股票名、代码、行业
   - 总分、行业排名
   - 当前池子 / 是否被过滤 / warning 状态
2. 一级维度解释区
   - 四个一级维度拆解
3. 规则判断区
   - 硬过滤原因
   - warning 标签
4. 财务与同行对比区
   - 作为第二层内容展示

目标是让用户第一屏就知道“这只股票为什么值得看，还是为什么需要谨慎”。

### 8.5 历史运行 `/runs`

历史运行页要从“纯时间列表”升级为更产品化的 run 导航页：

- 每条 run 卡片更强调结果摘要和跳转价值
- 规则快照摘要与来源任务要更容易扫读
- 跳转首页、列表、行业、复盘的关系更清楚

### 8.6 Run 质量总览 `/run-review`

复盘页要强化“先判断这次有没有跑偏”。

建议结构：

1. 质量摘要区
   - 通过率
   - 重点池占比
   - warning 覆盖率
   - 平均 warning 数
2. 结论区
   - 这次 run 的风险提示和建议动作
3. 分布区
   - warning 分布
   - 行业分布
4. 异常样本区
   - 高分但 warning 多

复盘页不应像仪表盘堆卡片，而应像复盘报告首页。

### 8.7 规则实验台 `/lab`

实验台是本次改造中最重要的“工作台感”页面。

建议结构：

1. 页面摘要区
   - 当前规则版本
   - 改动摘要
   - 校验概览
2. 主编辑区
   - 硬过滤
   - 一级权重
   - 二级权重
   - 重点池名额
3. 右侧反馈区
   - 改动摘要
   - 错误与提醒
   - 提交区文案
   - 快照提示

实验台不再是单纯表单页，而是“实验驾驶舱”。

### 8.8 任务页 `/tasks/:taskId`

任务页应从“日志页”升级为“任务状态与结果入口页”：

- 第一屏先看状态、阶段、结果入口
- 日志和细节放在后面
- 与 run、首页、列表、行业、规则快照的跳转关系更清楚

## 9. 信息结构原则

每个页面都要遵循以下排序：

1. 当前上下文是什么
2. 结论 / 摘要是什么
3. 我下一步最该做什么
4. 详细数据和解释在哪里

这条原则要覆盖首页、列表、详情、复盘、任务页和实验台。

## 10. 实现建议

### 10.1 优先改造顺序

建议按以下顺序落地：

1. 全局色板与 `AppShell`
2. `Panel` / `MetricTile` / `StatusPill`
3. 首页 `/`
4. 股票列表 `/stocks`
5. 个股详情 `/stocks/:tsCode`
6. Run 复盘 `/run-review`
7. 历史运行 `/runs`
8. 任务页 `/tasks/:taskId`
9. 规则实验台 `/lab`
10. 行业看板 `/industries`

### 10.2 原则

- 先统一视觉骨架，再逐页微调
- 优先复用现有业务组件
- 不在这轮里引入新的复杂交互范式
- 保持现有数据流与 API 调用方式不变

## 11. 风险

- 如果 Apple 感过强，容易把工作台做成宣传页
- 如果浅色和留白做得过度，列表和实验台可能失去效率
- 如果表格改造只关注样式，不关注排版密度，会影响真实使用
- 如果不同页面各自发挥，最后会失去统一设计系统

## 12. 验收标准

完成后应满足：

- 第一眼更像成熟产品，而不是内部工具
- 首页、列表、详情、实验台、复盘页属于同一套视觉系统
- 关键结论更容易先被看到
- 数据阅读效率没有因为视觉升级而下降
- 用户可以明显感知“Apple 官网感”，但不会误认为是营销站
